## 2. 已完成并验收

### 工程与数据边界

- 新建独立 Mod `MoonWorld`，没有覆盖 `HolyGrailWarTest`。
- 身份与静态数值使用 `ServantIdentityDef`、`ServantResourceProfileDef` 和 `ServantAutonomyProfileDef`。
- 契约关系和存在状态只由 `CompServantState` 保存。
- 御主与从者当前魔力分别由原版 Need 保存，不在组件中复制数值。
- 灵基受损和断供进度分别复用 Hediff severity 与 `ageTicks`。

### 御主魔力与供魔

- 魔术回路 Trait 通过 `DefModExtension` 引用回路 Def；魔术师位阶只作身份标签。
- 御主自然回魔、可调整供魔安全线、多从者均分和满魔退出均分池已经实现。
- 实体及灵体从者均可接受御主供魔。
- 从者原版自然饥饿下降关闭；实体化时按 10:1 将食物储备转化为魔力，并在原版进食边界停止。

### 从者身份、生理与自治

- 从者没有睡眠需求，不患疾病，不受衰老、寿命和饥饿归零惩罚。
- 己方契约从者使用 `Faction.OfPlayer` 与空 `HostFaction`；实体允许原版工作、征召、移动和从自身施放能力，保留角色背景与健康的原版限制。
- 顶部头像使用原版成员列表，灵体头像灰显；从者自身命令栏显示魔力和形态命令，御主保留召唤、令咒及形态入口。
- 原版工作、作息、心情、社交和人口规则继续适用；不新增临时成员标记或虚构任务。
- `ServantColonyMembership` 在绑定及完整载入时处理旧 Guest 转换，保护 PawnKind 和魔力，保留工作优先级及旅行 Lord；周期状态校正不再更改派系或移除 Lord。
- 删除 6 个 Guest 专用旅行补丁，使用原版殖民者名单与装载流程，保留契约同队验证及灵体登舱 Job。旧 `LordJob_ServantGuest` 类型保留供反序列化。

### 灵体化与战败

- 主动灵体化可通过御主或从者自身入口调用同一契约校验与生命周期服务；战败可进入战败灵体化。
- 灵体全部人物渲染层为 30% 不透明，普通目标无法索敌。
- 灵体只跟随御主，移动速度为原版速度的 300%；正常距离使用原版寻路，超过阈值时闪现追上。
- 灵体停止流血、不能攻击、工作或施放能力；不可站立格不能实体化。
- 普通伤害导致原版倒地或死亡时进入战败；直接 `Pawn.Kill` 不拦截。
- 战败时只最低限度修复致命状态，魔力清零并增加一级灵基受损；伤势仍会导致倒地或死亡时不能实体化。
- 御主死亡后，其未湮灭从者立即湮灭。
- 灵体化立即解除征召并清除优先工作与命令队列；保持可查看状态，禁止普通玩家移动、工作、征召、攻击和施法。

### 测试宝具与令咒

- `测试宝具_魔力爆发` 为角色 Ability，从者自身通过原版选点与施法 Job 释放；40 魔力、30 格射程、1 秒吟唱、3 格爆炸半径、40 Bomb 伤害、300 Tick 冷却，复用原版显眼高爆特效与音效。
- `NoblePhantasmService` 负责有效性、魔力费用、过载和失败回滚；AbilityTracker 保存能力与冷却。当前具体效果仍是 Bomb Explosion，尚未接入原型 Excalibur。
- 御主“宝具过载”消耗一枚令咒，在目标身上保存一次性 Hediff；下一次成功 MoonWorld 宝具免魔力且伤害翻倍，失败/取消保留过载。
- 奇迹重铸清除从者伤势、疤痕及灵基受损；御主令咒数量仍由原组件保存。

### 神秘度与自愈

- 当前白名单只允许实体化英灵造成的攻击伤害实体化英灵；环境伤害可以生效，直接处决不拦截。
- 普通伤口和疤痕按严重度逐点消耗维持线以上的魔力恢复。
- 背痛、虚弱等非伤口有害状态使用原版 `HealthUtility.Cure` 治愈，默认固定消耗 40 点维持线以上的魔力。
- `Hediff_MissingPart`、植入物和 MoonWorld 系统 Hediff 不进入肉体自愈候选。

## 4. 当前模块化审查

身份迁移已验收。成员转换位于 `Lifecycle/ServantColonyMembership`，灵体移动位于 `Autonomy`，玩家 UI 位于 `Presentation`；不继续围绕 Guest 增加控制补丁。

以下是后续触碰对应模块时再处理的结构信号：

1. 无消费者的 `IServantAutonomyPolicy` 与旧 Guest 初始化服务已移除，旧存档 LordJob 类型仍保留。不要为未来敌方行为预建自治注册表。
2. 文档曾规划 `IPranaSource`，代码尚未建立通用魔力来源接口；新增第三种魔力来源时先确立来源契约，不继续向 `PranaCycleService` 堆分支。
3. `GameComponent_MoonWorld.warStartTick` 已从魔力文件分离，当前仍是公开字段，正常召唤通过幂等方法写入；未预建阶段二状态。
4. `lordJobKey` 与 `targetPriorityKey` 当前没有运行时消费者。不得围绕字符串建立大型分支；等多策略需求出现后再改为真实 Def 或策略引用。
5. 构建脚本当前不是二进制确定性构建，相同源码重复编译仍会改变 DLL。以后可单独修正构建参数，不能把这种二进制变化误当作功能修改。

## 6. 下一开发切片

建议名称：Excalibur 角色 Ability 接入（尚未开工）。

目标：按用户此前“先验证测试宝具，再迁移 Excalibur”的顺序，将阿尔托莉雅的正式宝具挂到角色 Ability，复用已经验收的魔力、令咒过载与冷却规则，并保留可辨认的原型光束表现。

本轮边界：

1. 原型 `CompExcaliburNoblePhantasm` 当前为武器组件，`ExcaliburVfxThing` 同时拥有视觉和持续伤害；不得直接调用旧入口造成绕过扣费、双按钮或重复伤害。
2. MoonWorld 当前结算服务直接创建 Bomb Explosion，需要在真实第二个消费者接入时分离共同结算与具体效果；不预建通用能力注册表。
3. 原型继续作为内容依赖，源码与安装文件不修改；正式宝具属于角色，武器是否持有不决定能力所有权。明确 MoonWorld 契约角色的旧武器入口处置及中断边界后再实施。
4. 测试宝具保留为回归消费者；不进入敌方战争、三阶索敌、信赖控制或完整内容迁移。正式费用与伤害参数在接入评估中明确，不把原型逐 Tick 伤害直接等同于测试爆炸数值。

验收：

- 从阿尔托莉雅自身 Ability 发起 Excalibur，选点、光束、声音和命中范围正确；无绕过结算的重复入口。
- 魔力、过载、冷却与伤害归属只结算一次；灵体、魔力不足、取消或初始化失败不留下错误费用及伤害。
- 持续效果、中断和读档策略有明确规则，测试宝具仍通过原有回归。
- 构建部署后由用户确认实际游戏表现；通过后再记录验收和推送。

## 7. 工作约束

- 优先复用 RimWorld 1.6 原版 Need、Hediff、Job、Lord、Ability、Quest 和 Gizmo 机制。
- 每个功能保持独立模块；Harmony 只作窄入口，不保存状态或承担完整业务流程。
- 不预建阶段二状态字段，不引入没有实际消费者的接口或注册表。
- 不覆盖 `HolyGrailWarTest`；当前作为内容依赖，后续正式迁移另行评估。
- 每次修改后运行 `Source\build.ps1 -Deploy`，同步到游戏 Mod 目录并由用户完成真实游戏验收。
- 未经用户确认，不新增硬依赖、不重写模块、不删除旧存档兼容类型。
