# 契约从者玩家成员迁移设计

本文定义本次已授权迁移的影响与验收合同，不记录完成进度。进度仍只由 `docs/PROJECT_STATUS.md` 记录。

## 行为合同

- 已契约的己方从者使用 `Faction.OfPlayer`、空 `HostFaction`，通过原版殖民者路径工作、征召、显示顶部头像和自身 Ability。
- “契约从者”由已有身份 Def 与 `CompServantState` 识别，不增加临时成员布尔值、反向索引、任务或计时离开状态。
- 实体允许原版工作、直接战斗和自身宝具；灵体保留查看、契约操作和原版旅行登舱通路，禁止普通工作、征召、攻击及施法。
- 御主继续持有召唤、令咒重铸与过载。宝具由从者自己释放；形态命令可以从双方入口调用同一生命周期服务。
- 仅转换已有己方契约 Guest；普通访客、囚犯、奴隶、敌方角色、未绑定原型角色与已湮灭者不被自动归队。

## 原版证据与影响

核对对象为本机 RimWorld 1.6 `Assembly-CSharp.dll`，反编译参考在仓库外 `../tmp/assembly-inspection`。

| 范围 | 证据 / 风险 | 迁移决策与验证 |
| --- | --- | --- |

## 分批与回退

1. 身份与旧档：生成派系、集中迁移、局部身份保护、状态校正与同行识别；预计生产代码约 150 行，另有独立宿主替身测试。
2. 操作与表现：从者魔力 Gizmo、自身形态入口、原生 Ability 展示、灵体征召/命令门控和头像灰显；不修改宝具结算数值。
3. 旅行适配与验收：删除 Guest 补丁，保留同队约束；补充原版机制与静态目标校验、完整游戏冒烟步骤。

每批检查 diff、编译和对应测试，生成单独本地提交。后批依赖前批，整体回退按反序执行 `git revert`；应使用迁移前的独立存档备份，代码回退不会自动恢复已经另存的玩家派系身份。未通过游戏内验收前不推送。

## 验收门槛

- 构建通过，所有离线测试通过，部署文件匹配，已知回归清零。
- 新召唤与旧档的实体/主动灵体/战败灵体均通过 `docs/MVP_Smoke_Test.md` 的迁移矩阵。
- 普通访客不出现顶部头像；从者可工作、查看魔力、从自身施放一次结算一次的测试宝具；灵体不可绕过操作限制。
- 商队及运输舱正常集合、同队离图、取消、返回、保存读取，不能拆开御主和从者。
- 合同、身份、衣装、魔力、令咒、能力冷却和首次开战时间没有丢失或重置；日志无新增 MoonWorld 错误。
- 自动测试不等价于 Unity / HAR 渲染、完整 AI 或真实存档验收；游戏内验收由用户确认，发现的问题继续修复后复测。

不扩大到敌方战争、信赖控制、Excalibur 迁移、新依赖、世界地图供魔扩展或新的持久字段。
