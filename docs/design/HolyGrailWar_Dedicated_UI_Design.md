# MoonWorld 圣杯战争专属 UI 设计

状态：视觉预览已获用户确认；阶段 B 只读窗口已实现，等待 RimWorld 实机与用户验收。

本文先冻结信息架构和信息边界，不代表本批已经修改运行时代码，也不代表功能已经验收。

## 1. 设计目标

MoonWorld 的战争信息目前分散在战争任务描述、信件、原版地图检查器和调试菜单中。专属窗口应成为玩家查看战争状态的唯一入口，解决四个问题：

1. 玩家能在一个窗口内理解战争处于什么阶段、谁仍有资格、当前哪里正在交战。
2. 玩家能区分“尚未发现”和“已经确认不存在”，而不是把未知内容显示成假数据。
3. 侦察进度、现场目击和主从详情能分别解锁。看到从者不自动代表已经看见御主，反之亦然。
4. UI 只读取现有战争状态，不复制生命、魔力、契约和派系关系等权威数据。

本设计参考官方《Fate/stay night》资料中的七名御主、七名从者、职阶、主从契约和令咒资格等稳定要素；不同 Fate 作品的规则并不完全相同，MoonWorld 的战争节奏、侦察阈值和地点规则以本项目已经验收的规则为准。

## 2. 原作要素与 UI 转化

官方资料给出的 UI 锚点如下：

- 圣杯战争是七名御主召唤七名英灵，从者按 Saber、Archer、Lancer、Rider、Caster、Assassin、Berserker 七个职阶参与战斗，目标是决出最后存续的一方。
- 主从契约是参战关系的基础，御主通过令咒对从者拥有强制性的命令权。
- 令咒最多三划；令咒耗尽或失去资格会影响御主继续参战。
- 从者拥有职阶身份和宝具，但宝具的具体名称、能力和数值不应在尚未侦察时凭空展示。

这些要素转为界面时只保留玩家需要做判断的信息：席位、存续状态、契约状态、令咒资格、已知身份、已知地点和当前交战。宝具详细描述属于后续能力/魔术模块，不纳入第一版战争面板。

## 3. 入口与窗口布局

新增一个玩家可见的 `圣杯战争` 窗口，使用 RimWorld 原生 `Window`、`Widgets` 和 `Listing_Standard` 绘制，不依赖外部 UI 框架。

建议入口优先挂在现有圣杯战争任务的可点击入口或战争信件上；第一版不做常驻大 HUD，也不把调试菜单暴露给正常玩家。窗口打开后默认显示“总览”，窗口关闭和重新打开不改变战争数据。

窗口采用三栏密度：

```text
┌────────────────────────────────────────────────────────────┐
│ 圣杯战争  试探阶段   第 2 天 / 距终局强制决战约 8 天        │
│ 玩家席位：Saber  御主：已确认  令咒：2 / 3  战争：进行中     │
├──────────────┬──────────────────────────────┬──────────────┤
│ 总览           │ 当前页内容                   │ 选中对象详情   │
│ 情报           │                              │               │
│ 战况           │                              │               │
│ 主从           │                              │               │
│ 据点           │                              │               │
│ 图鉴           │                              │               │
└──────────────┴──────────────────────────────┴──────────────┘
```

小屏幕或 UI 缩放较大时，右侧详情栏折叠为点击列表项后出现的详情窗口；信息不能因为窗口变窄而相互覆盖。

## 4. HTML/CSS 可行性与绘制方案

RimWorld 的窗口不是浏览器页面。Unity IMGUI 有一个有限的富文本标记功能，`GUIStyle.richText = true` 后可以使用 `<b>`、`<i>`、`<size>` 和 `<color>` 等 HTML 风格标签；它不提供完整 HTML、CSS、DOM、Flex/Grid、CSS 渐变或 JavaScript。富文本只负责一段文字的字形和颜色，不能替代面板布局。

因此采用以下组合：

- 布局：`Window`、`Rect`、`Widgets`、`Listing_Standard`，所有栏位使用稳定的最小高度和滚动区。
- 文字：为标题、标签、状态和正文分别创建 `GUIStyle`，只有确实需要混排时开启 `richText`；动态文本仍通过安全的字符串格式化生成。
- 底色：用 `Widgets.DrawBoxSolid` 和少量可复用的纯色纹理绘制暗红面板、红色状态条和黑红内容区。
- 边框：用 `Widgets.DrawBox`、细矩形线和四角装饰绘制金框；不要依赖 CSS border 或运行时生成复杂网格。
- 装饰：第一版使用几何圣痕、菱形节点、短金线和中央徽记。若后续加入 PNG，资源必须放在 Mod 自己的 `Textures` 目录，并提供缺失纹理时的纯色回退。
- 交互：用 RimWorld 原生按钮、tooltip、滚动条和选中高亮；按钮状态不能只靠颜色表达。

参考图只作为气氛和构图参考，不作为需要逐像素复刻的界面规格。尤其不把大幅角色立绘、网页式背景或外部图片加载作为第一版运行时依赖。

## 5. FATE 红底金框视觉规范

目标是“魔术师仪式记录板”，而不是普通调试报告。视觉层次从外到内依次为暗色遮罩、红黑主体、金色结构线、象牙文字和宝石色状态点。

### 5.1 色板

| 用途 | 建议颜色 | 使用规则 |
| --- | --- | --- |
| 窗口外部遮罩 | `#18060D` | 只作背景，不承载信息 |
| 主体绯红 | `#260711` | 取红色披风的深红方向，作为大面积底色 |
| 内容猩红 | `#641322` | 卡片和当前页内容区 |
| 金色边框 | `#B9892E` | 结构线、标题下划线、四角节点 |
| 高亮金 | `#F1D27A` | 当前页、玩家席位、重要倒计时 |
| 象牙文字 | `#F5EBD0` | 正文和已确认身份 |
| 敌对红 | `#F20D21` | 交战、突袭、危险提示 |
| 未知琥珀 | `#C69A45` | 未侦察、地点未确认 |
| 存续青绿 | `#55C7B2` | 存续、契约有效、完成情报 |
| 退场灰 | `#77717A` | 失去资格、湮灭、已结束 |

红色只用于主体和危险状态，不能让所有文字、按钮和边框都变成红色。金色负责结构，象牙色负责阅读，青绿和琥珀负责状态区分；这样才能保持截图所需的层次感并兼容 RimWorld 的低分辨率字体。

### 5.2 结构与动效

- 窗口标题使用大一档象牙字，标题下方一条金色横线，两端各有菱形节点。
- 左侧页签使用窄金框；当前页签为暗红底加高亮金字，未选页签为黑红底加象牙字。
- 总览席位卡使用“金色外框 + 暗红内底 + 左侧职阶徽记位 + 右侧状态条”。没有真实图标时显示几何职阶首字母或统一圣杯纹样，不绘制假头像。
- 交战卡使用左右对置的双栏结构，中间放一个小型金色 `VS` 标记；它借鉴参考图的对抗关系，但不占据窗口大部分空间。
- 令咒显示为最多三枚小型菱形印记，已用、有效和未知使用不同填充色；敌方令咒不显示精确数量。
- 状态条只表示“存续/交战/未知/退场”等有限状态，不把敌方未知生命或魔力伪装成进度条。
- 第一版不加入持续闪烁、粒子和全屏转场。可以使用低频率的当前页高亮，但窗口信息必须在暂停和低帧率时仍清晰可读。

### 5.3 页面密度

默认窗口建议约为屏幕宽度的 70% 至 82%、高度的 72% 至 84%，并设定最小尺寸；不把内容铺满全屏。总览页突出“当前阶段 + 存续席位 + 正在发生的事件”，情报页突出“解锁轨道”，详情页突出“主从关系”。装饰元素的面积不超过可用内容区的约 15%。

## 6. 顶部战争栏

顶部区域在所有页面保持一致，只显示全局信息：

| 字段 | 显示内容 | 权威来源 | 备注 |
| --- | --- | --- | --- |
| 战争名称 | 圣杯战争 | `GameComponent_MoonWorld`/Quest | 固定标题，可留出未来届次名额 |
| 阶段 | 试探阶段、激烈阶段、终局阶段 | `WarRhythmPolicy.PhaseLabel` | 不另算 UI 阶段 |
| 经过时间 | 第几天、当前 Tick 转换的时间 | `warStartTick` 与当前 Tick | 只读 |
| 决战倒计时 | 距第十天强制圣杯决战的时间 | `WarRhythmPolicy.FinalBattleDue` 相关计算 | 战争已结束时改为结果 |
| 战争结果 | 进行中、玩家胜利、玩家败北 | `CurrentWarOutcome` | 结果优先于阶段 |
| 存续席位 | 尚未失去资格的席位数 / 总席位数 | `CurrentWarEntry.Participants` | 总席位从参与者实际列表读取，不硬编码为七 |
| 玩家主从 | 玩家席位、御主、从者 | `CurrentWarEntry` 与现有契约服务 | 缺失时明确显示未绑定或失去资格 |
| 令咒 | 当前令咒 / 最大令咒 | `CompMasterCommandSpells`、`CommandSpellService` | 只显示玩家御主的精确数值 |

“第十天”是当前 MoonWorld 的强制决战规则；它不是通用 Fate 规则，文案应避免把它描述成原作固定设定。

## 7. 英灵详情与图鉴

### 7.1 当前记录详情

总览、情报、战况和主从页中的已知从者可以打开独立的“英灵档案”窗口。窗口沿用原版 Status Menu 的信息组织：顶部显示职阶和称号，正文分为基本资料、参数、职阶能力、宝具、人物记录和当前状态。静态设定字段来自 MoonWorld 的 `ServantLoreDef`；动态存在状态、契约、魔力和位置仍读取当前 Pawn 与战争状态。

只有玩家自己的从者显示精确魔力；敌方英灵即使身份已知，也只显示已知的静态设定和允许公开的定性状态。敌方精确生命、伤势、装备和魔力继续通过原版地图检查器查看。

### 7.2 英灵图鉴

战争窗口左侧新增“图鉴”按钮，打开独立的英灵资料库。资料库按已安装且进入召唤池的 `ServantIdentityDef` 汇总，可按 Saber、Archer、Lancer、Rider、Caster、Assassin、Berserker 和“全部”筛选。每个条目可以打开完整静态详情。

图鉴是内容库，不是本届战争的侦察结果。浏览图鉴不会解锁敌方席位的从者、御主或据点情报；条目旁应标注“资料库信息，不代表本届已召唤”。没有配置静态资料的扩展英灵仍可出现，但详情显示“尚未配置静态设定卡”，不得自动猜测身世或参数。

## 8. 总览页

总览页是默认页，以席位卡片展示当前参战阵营。卡片按照 `CurrentWarEntry.Participants` 的顺序排列，玩家席位置顶，其余席位按职阶排序。

每张卡固定包含：

- 职阶/席位：已解锁时显示 Saber 等名称，未解锁时显示“未知席位”。
- 阵营状态：参战中、休整、交战中、失契待重契约、已退场、已失去资格。
- 从者：名称只在 `WarReconnaissanceService.KnowsServant` 为真时显示；否则显示“未知从者”。
- 御主：名称只在 `WarReconnaissanceService.KnowsMaster` 为真时显示；否则显示“未知御主”。
- 据点：只在 `KnowsSite` 为真或属于玩家时显示位置和工坊状态；否则显示“地点未确认”。
- 当前活动：无活动、野外交战、约战等待、约战地图、工坊出击、休整或重建中。

卡片颜色只表达状态，不表达身份可靠性：玩家使用绿色，正在交战使用红色，已知但未活动使用中性颜色，未知信息用黄色标记，退场使用灰色。不要为每个职阶添加一套固定颜色，以免颜色同时承担职阶和危险程度两种含义。

## 9. 情报页

情报页是侦察系统的主界面，每个敌方席位一行，显示三条彼此独立的解锁轨道：

| 轨道 | 解锁条件 | 解锁后可显示 | 未解锁显示 |
| --- | --- | --- | --- |
| 从者身份 | 侦察进度达到 34，或实际看见非迷雾中的敌方从者 | 从者名称、职阶、存在状态 | 未知从者 |
| 御主身份 | 侦察进度达到 67，或实际看见非迷雾中的敌方御主 | 御主名称、资格状态、契约概况 | 未知御主 |
| 据点情报 | 侦察进度达到 100 | 工坊位置、是否失守、重建状态 | 地点未确认 |

实际看见从者与实际看见御主必须分别记录。一个角色进入玩家可见地图只解锁对应角色，不能连带解锁另一角色；普通殖民者在约战地点路过也不改变约战到场规则。

进度条只显示真实 `WarReconnaissanceRecord.Progress`。在 0、34、67、100 之外不添加虚假的中间情报。每条轨道旁显示来源标签：侦察进度、现场目击或玩家自有信息。第一版不增加“推测”状态，避免玩家把推测当作事实。

情报页的行点击后进入详情栏，详情栏必须继续应用相同的解锁检查，不能因为打开详情而绕过信息门槛。

## 10. 战况页

战况页只展示当前可由现有运行时状态证明的活动：

### 7.1 当前敌方互攻

当 `enemyBattle` 存在时显示：

- 进攻方和防守方的席位/身份，分别应用情报解锁。
- 野外地点或工坊地点；地点未知时只显示“交战地点未确认”。
- 交战已进行回合数和下一回合时间。
- 地图状态：场外回合、地图已生成、双方是否仍在地图内。
- 玩家可知的结果：交战中、某方退场、交战结束。

双方的精确生命、伤势和魔力仍由原版 Pawn、`CompServantState` 和 `Need_Prana` 提供。战争窗口第一版只显示玩家自己的精确数值；敌方显示定性状态，点击已知地点后使用原版检查器查看实时细节。

### 7.2 当前约战

当 `enemyChallenge` 存在时显示：

- 发起约战的从者及其御主，分别应用情报解锁。
- 临时地点是否已生成。
- 绝对到期时间和“已到场/等待/已结束”。
- 玩家到场资格提示：本届玩家御主或从者到场才算赴约。

超时只显示约战结束，不显示“自动转为基地突袭”。这符合当前已确认规则。

### 7.3 终局事件

`finalBattleTriggered` 为真时显示圣杯决战状态：触发时间、敌方席位数量、玩家基地地图是否生成、各敌方从者是否仍在战斗。敌方在决战中仍互相敌对，窗口不能把所有敌方单位合并成单一阵营。

## 11. 主从页与详情

主从页用于比较一个席位的两名核心角色，不新增一套角色数据。

从者详情：

- 名称、职阶、所属席位：依 `KnowsServant` 门槛显示。
- 存在状态：物质化、灵体化、战败灵体、湮灭等，来自 `CompServantState.PresenceState`。
- 契约御主：仅在御主已知且当前契约存在时显示；改属时显示当前契约关系，同时保留已知的原始御主标签。
- 活动状态：出击、休整、约战、交战、容器/地图外等由现有服务状态推导。
- 魔力和伤势：玩家自己的从者显示精确值；敌方只显示定性状态，除非玩家正在使用原版地图检查器。

御主详情：

- 名称和席位：依 `KnowsMaster` 门槛显示。
- 令咒资格：玩家御主显示精确令咒；敌方只显示有效、失去资格或未知。
- 当前契约：显示已绑定、失契待重契约、改属或无契约。
- 存活状态：来自 Pawn 的真实状态。
- 位置：只在玩家可知的据点或当前玩家地图中显示，不根据全局 Pawn 引用直接泄露坐标。

宝具和具体能力不在第一版自动展开。已有能力面板或原版检查器仍是能力详情的权威入口。

## 12. 据点页

据点页按已知地点列出工坊和临时约战地点：

- 工坊所属席位和主人：应用情报门槛。
- 世界坐标和地图按钮：玩家自有或 `KnowsSite` 为真时可用。
- 工坊状态：正常、从者出击、失守、等待重建。
- 约战地点：临时、无工坊所有权、无额外守军和战利品；结束后从列表清理。

临时约战地点不能被 UI 当成敌方工坊，也不能在窗口中出现“重建”或“所有权”按钮。直接突袭仍通过原有业务入口处理，战争窗口只显示其当前结果或活动状态，不复制一条新的突袭业务。

## 13. 数据边界与未知状态

以下对象是第一版 UI 的唯一数据来源：

- `GameComponent_MoonWorld`
- `HolyGrailWarEntry`、`EnemyWarParticipant`
- `WarReconnaissanceRecord` 与 `WarReconnaissanceService`
- `EnemyBattleSession`、`EnemyChallengeSession`
- `Site_WarWorkshop`、`Site_WarEncounter`
- `CompServantState`、`CommandSpellService`、`CompMasterCommandSpells`
- `Need_Prana` 和现有战争/契约服务

UI 不应：

- 自己缓存 Pawn 的生命、魔力、契约或派系；
- 用“看见从者”推断“看见御主”或“看见据点”；
- 用席位顺序推断未侦察的真实身份；
- 用敌方 Pawn 的全局引用直接显示未解锁坐标；
- 用调试菜单中的字符串作为正常玩家 UI 的业务接口；
- 把缺失对象渲染为满血、满魔力或默认存活。

对象不存在时使用明确状态：未召唤、失联、已退场、已销毁或数据不可用。无法证明的字段显示“未知”，不能使用猜测值。

## 14. 分阶段实现

### 阶段 A：设计冻结

本文件完成后由用户确认信息架构、解锁门槛和数据边界。此阶段不改运行时代码，不部署。

### 阶段 B：只读 MVP

实现 `Window_HolyGrailWar` 和一个玩家入口，包含顶部战争栏、总览页、情报页、主从页和基础详情栏。只读取当前字段，不新增持久化事件日志。

验收重点：

- 两阵营旧存档和七席新战争都能打开；
- 玩家席位始终可见，敌方从者和御主按独立门槛显示；
- 读档后阶段、进度、身份解锁不丢失；
- 未知字段没有通过 Pawn 引用或详情窗口泄露。

### 阶段 C：战况与据点集成

接入当前敌方互攻、约战、工坊重建和圣杯决战状态，允许对已知地点调用原版地图/检查器。仍不在 UI 中新增战斗或突袭逻辑。

验收重点：

- 场外交战、地图交战、离图续战能正确切换显示；
- 约战等待、到期、撤出不误显示为突袭；
- 临时地点清理后不会残留在据点页；
- 第十天决战显示多个敌方席位互相敌对。

### 阶段 D：战况历史

如果用户确认需要“战况记录”而不是“当前战况”，再新增有上限的持久化 `WarEventRecord` 列表，记录事件类型、发生 Tick、涉及席位、结果和情报来源。历史记录必须独立于 Pawn 实例，限制条数并兼容旧存档；在此阶段前不在 UI 中伪造历史列表。

## 15. 视觉与交互验收

- 使用暗红主体、金色结构线和紧凑行高，优先扫描和比较；装饰只服务于层级，不遮挡信息。
- 每一行信息都有稳定高度；未知文本过长时换行或裁剪到 tooltip，不挤压相邻字段。
- 颜色只表达玩家/敌对/未知/退场/当前活动等状态，文字仍必须完整表达状态。
- 点击席位、事件和地点只执行已有的选择、检查器或地图打开动作；不存在的动作不显示为可点击按钮。
- 战争结束后窗口保留最终席位和结果快照，但实时活动区显示已结束，不继续读取失效会话。
- 自动化测试只验证状态映射和解锁边界；真实窗口尺寸、原版字体、地图跳转和玩家是否认为信息足够，必须经过 RimWorld 实机验收。
