# 《RimWorld》圣杯战争（Holy Grail War）玩法机制与灵感设计案

> **定位说明**：
> 本文档旨在为型月宏大世界观（魔术、英灵、死徒及其他体系）中的核心大型模块——**【圣杯战争】**，提供纯粹的**玩法规则、循环逻辑与设计灵感**。
> 本设计案不预设或锁死底层代码的具体实现手段，仅作为后续系统设计与工程开发的顶层指导准则。

---

## 一、 顶层定位：型月四大体系架构

在规划圣杯战争模块之前，确立型月宇宙的四大基石体系，确保模块间高度解耦且具备长期联动扩展性：

```text
┌─────────────────────────────────────────────────────────────┐
│                    型月世界四大宏观体系架构                  │
├──────────────┬──────────────┬──────────────┬────────────────┤
│  魔术体系    │  英灵体系    │  死徒体系    │  其他扩展体系  │
│ (Magecraft)  │  (Servants)  │ (DeadApostle)│ (Cosmic/Outer) │
├──────────────┼──────────────┼──────────────┼────────────────┤
│ • 魔术回路   │ • 灵基与从者 │ • 纯正吸血种 │ • 钢之大地     │
│ • 魔术刻印   │ • 契约与令咒 │ • 死徒二十七祖│ • 苍辉银河     │
│ • 工房与使魔 │ • 宝具与解放 │ • 真祖与血戒 │ • 宇宙神性/外神│
│ • 大源/小源  │ • 人理抑止力 │ • 星球抑止力 │ • 真以太环境   │
└──────────────┴──────────────┴──────────────┴────────────────┘
```
* **本模块聚焦点**：**圣杯战争**是**魔术体系**（御主、地脉工房、魔力）与**英灵体系**（从者、灵基、宝具）深度交织碰撞的大型闭环战役事件。

## 二、 MVP 实施边界与后续计划

### 1. 当前 MVP：单御主、单从者的核心闭环

当前 MVP 以已经落地的阿尔托莉雅和卫宫为验证对象，只实现一名御主与一骑契约从者的可玩闭环：

* 御主召唤、契约、令咒和 `warStartTick` 开战记录；
* 御主回路自然回魔、供魔安全线、向实体化从者供魔，以及从者进食转魔的辅助补给；
* 从者实体化、主动灵体化、战败灵体化、灵基受损与御主死亡后立即湮灭；
* 从者按原版任务临时成员契约自主行动，不开放玩家直接移动、工作分配或征召；战斗目标遵循英灵、御主、其他目标的优先级；
* 仅英灵施放的攻击可以伤害实体化英灵；其他攻击在原版伤害应用前被拦截；
* 环境伤害可正常伤及实体化从者；从者免疫疾病、衰老、老年死亡及饥饿值归零的原版惩罚。

供魔结算按多从者兼容方式实现：仅把未满魔的实体化契约从者纳入均分池；从者满魔后退出该池，直至全部满魔，御主再继续积累自身魔力。每个低频结算周期固定按“御主自然回魔 -> 实体化从者进食转魔 -> 分配御主溢出魔力 -> 从者维持消耗与断供判定 -> 维持线以上的自愈”执行。MVP 内容上仍只生成一骑己方从者，不建立完整敌方据点、自动战争胜负或七职阶池。

### 2. 后续阶段

* **阶段二：战争闭环**。敌方御主与从者、据点、突袭、战争胜负和时间压力；
* **阶段三：内容与数值扩展**。新增英灵、六维参数的正式映射、其他具备神秘度的攻击来源和更多供魔来源；
* **阶段四：长期系统**。信赖后的控制权、真名情报、地脉工房、七职阶池及跨地图/商队的完整规则。

后续阶段不得反向要求 MVP 预存未使用的状态字段；仅保留能通过静态 Def 或运行时查询自然扩展的边界。

### 3. 工程模块边界

圣杯战争是 `MoonWorld` 型月世界总 Mod 的子模块，不能以独立测试 Mod 的方式继续堆叠功能。其数据归属、公开接口、调用方向和开发顺序以 [HolyGrailWar_Module_Boundaries.md](../HolyGrailWar_Module_Boundaries.md) 为准：跨模块只能使用该文档列出的查询或状态转换接口；表现层不得写入玩法状态；原版 Need、Hediff、Quest、Lord 与 Pawn 仍是优先复用的底层载体。

## 三、 核心机制一：魔力双轨制与“断供缓冲-灵基创伤”体系

英灵并非普通血肉之躯，其运转必须依赖持续的“魔力”维系。将状态划分为两条清晰的逻辑层：**临时性的【魔力断供】缓冲**与**阶梯式的永久【灵基受损】创伤**。

```text
[ 0% ] ── 枯竭危险区 ── [ 维持基准线 (如30%) ] ── 自由战斗调度区 ── [ 100% 最大魔力上限 ]
        ▲                                              ▲
   触发临时【魔力断供】                               宝具释放 / 战术技能消耗
   （带恶化计时缓冲）
        │ （若长期未恢复 或 战败倒地）
        ▼
   获得永久阶梯【灵基受损】（类似永久伤痕）
```

### 1. 魔力结构与自由战斗池
* **维持基准线（Base Sustenance Threshold）**：
  * 英灵维持稳定现世所需的最低魔力警戒线。
  * **基准线以上**：从者处于满状态运作，盈余的魔力用于普通攻击强化、技能施放与宝具解放。
  * **跌破基准线**：进入“魔力饥渴/断供”状态。
* **御主主供给与辅助回魔**：
  * 御主魔术回路的自然恢复是当前阶段从者魔力的主要外部供给；御主魔力高于【供魔安全线】的溢出部分，自动均分给其名下所有处于实体化状态的契约从者。
  * 御主魔力降至安全线时，常规供魔自动断开，从者改为消耗自身储备；御主仍可在安全线以下自然恢复。
  * 进食转魔是从者自身的低效率辅助回魔途径，与御主供魔并存，不参与御主魔力池的分配计算；后续可以通过独立模块加入其他魔力来源。
* **低频结算顺序**：每个统一魔力结算周期先恢复御主魔力，再让实体化从者将食物储备转化为魔力，随后分配御主高于安全线的全部溢出魔力；最后依次处理从者维持消耗、断供判定与维持线以上的自愈。该顺序不引入独立供魔通道速率或额外存档变量。

### 2. 第一层：临时性【魔力断供 / 灵基虚脱】（可逆的急性缓冲）
* **定位**：给玩家一个容错与抢救的“缓冲气囊”，表现为急性掉电与疲软，**不直接对灵基造成永久破坏**。
* **生效与消除**：
  * 当英灵魔力跌破维持基准线时自动挂载；
  * **一旦魔力补充恢复至基准线以上，该 Debuff 立即自动清除，不留隐患**。
* **原版基础属性惩罚（实现简单、开箱即用）**：
  * **移动速度（MoveSpeed）**：轻度降低（例如 `-15% ~ -20%`），表现为肢体沉重、实体化不畅。
  * **操作能力（Manipulation）**：轻度降低（例如 `-10% ~ -15%`）。
  * **意识（Consciousness）**：轻度降低（例如上限锁在 `90%`）。
* **恶化计时（The Countdown）**：
  * 处于该状态时，内部附带一个恶化倒计时（如类似疾病严重度持续增加）。
  * 若玩家长时间放任不管（计时走满），则**触发深层反噬：清除本临时状态，并获得或加重一级永久性的【灵基受损】**！

### 3. 第二层：永久身体状态【灵基受损】（不可轻易逆转的深层创伤）
* **定位**：类似原版【永久伤痕 / 脑损伤】的深层结构性创伤。平时魔力补满后依然存在，代表英灵维持存在的结构性损伤。
* **获得途径（两条绝对规则）**：
  1. 临时【魔力断供】持续时间过长，恶化结算；
  2. 英灵在战斗中被击倒休克（Downed）或遭受致死创伤、触发灵体化回程时，**直接加深一级**！
* **阶梯式惩罚（直接使用原版身体效率 Capacity / 状态上限）**：
  * **阶段 1（灵基微裂）**：意识上限降为 `90%`，工作与劳作速度略微受限，带有轻度阵痛。
  * **阶段 2（灵基破损）**：意识上限降为 `75%`，移动速度上限降为 `80%`，近战与射击命中率出现明显衰减。
  * **阶段 3（灵基濒碎）**：意识上限降为 `50%`，伴随重度剧痛，日常极易脱力休克，基本丧失独立战斗能力，需长期静养。
  * **阶段 4（彻底湮灭）**：灵基完全崩解，从者肉身与灵体彻底消散死亡，正式从本次圣杯战争中除名。
* **修复逻辑（仅限令咒）**：
  * 无法通过普通草药、常规医药、生化手术或自然休息自愈；
  * **当前阶段唯一修复手段：消耗御主的 1 划令咒**，奇迹般瞬间抚平并彻底清除目标英灵身上的所有【灵基受损】状态。

## 四、 核心机制二：灵体化（Spirit Form）与自愈优先级法则

彻底打破传统“战败即死留尸”的粗暴机制，围绕型月核心设定引入【主动/战败灵体化】与【魔力自愈消耗法则】。

### 1. 灵体化机制（Spirit Form）与能耗
灵体化是从者作为纯魔力凝聚体的固有能力，分为“主动调度”与“战败强制脱离”两种形态：

* **主动灵体化（御主 Gizmo 指令）**：
  * **半透明与绝对避战**：地图上的身体、头发、衣物等全部 PawnRenderTree 人物层固定为 `30%` 不透明，但无法被任何敌对实体正常选定与攻击；小人栏头像常驻显示；
  * **功能锁定与御主跟随**：灵体化期间只执行跟随契约御主的移动，不工作、不进食、无法攻击或释放技能；灵体 Hediff 通过原版 `MoveSpeed` 统计倍率将移动速度提高至 300%，专用灵体跟随 Job 在正常距离内调用原版 Pawn 寻路，默认 4 格内停留，超过 10 格时闪现到御主周围 2 格内的原版可站立格。正常无遮挡移动主要依靠加速跟随，闪现只作为距离过远时的追赶兜底；闪现只更新灵体从者的位置，不开启或破坏沿途物体，也不修改实体 Pawn 的普通寻路；
  * **同图约束（Map Binding）**：**从者灵体化时必须与御主在同一张地图上**；
  * **离图约束**：御主尝试离开当前地图时，任何未湮灭的契约从者都必须已加入同一离图队伍；否则取消离图并提示原因，不传送或强制移动从者；
  * **状态判定权威**：灵体化状态由从者状态模块统一判定；MoonWorld 的表现补丁统一设置全 PawnRenderTree 节点透明度，原版心理不可见组件只负责透明材质通道与普通索敌层。目标选择、攻击、伤害、工作与环境伤害均须先通过灵体状态判定，不能只依赖表现 Hediff；
  * **能耗剧减与维持线降阈**：
    * 英灵现世默认拥有基础的魔力维持消耗速率；
    * **灵体化状态下，基础魔力维持消耗直接降低 75%**，同时【维持基准线】大幅下降，可极大缓解供魔紧张，避免在避难期间因魔力短缺误触发【魔力断供】与灵基受损；
  * **避险休养**：遭遇极端有毒落尘、辐射或据点失火时，可令从者灵体化彻底规避环境灾害。
* **物理进食与第二回魔途径（进食转魔）**：
  * **生理零衰减与绝对免疫饥荒惩罚**：
    * 英灵保留原版 `Need_Food` 数值作为食物营养储备，但**关闭原版自然饥饿下降**；饥饿度的下降只能由进食转魔模块产生；
    * **免疫原版饥荒后果**：该种族对 `Malnutrition` 及由饥饿值归零引发的减速、虚弱、昏睡、昏迷倒地和死亡不产生效果；该免疫必须覆盖原版实际生效路径，不能只依赖一个 XML 数值；
    * **支持食物配给限制**：玩家可在原版食物限制面板中随时将从者设为“无 / 禁食”以彻底节约粮食，从者完全不吃也不会受到任何惩罚（仅失去进食转魔渠道）。
  * **以食转魔逻辑**：
    * 仅实体化从者可进食或进行转魔；灵体化期间冻结 `Need_Food`，既不进食也不把食物储备转化为魔力；
    * 当且仅当实体化从者**魔力未满（CurrentPrana < MaxPrana）**且 `Need_Food` 高于转化阈值时，以太炉心才会缓慢消耗饥饿值并将其转换为魔力；
    * 转化阈值必须对接原版 `Need_Food` 触发进食 Job 的判定边界，而不是另写一套互相竞争的寻食阈值；
    * 当饥饿值降至该边界以下时，继续使用原版寻食与进食 Job，并遵守原版食物限制；进食补充饥饿值后，再由转魔模块继续转换；魔力满额时停止转化和进食；
* **从者身份模板与日常控制权（遵照任务临时成员规范）**：
  * **底层对接标准**：召唤后按原版任务临时成员（Quest Lodger）契约建立身份，复用其 Guest/Lodger 状态与 `LordJob` / `Duty` 自主行为；`Pawn_GuestTracker` 只承担访客关系状态，不能单独作为 AI 实现。不依赖 Anomaly DLC 的专属实体机制，也不得将从者按普通 `Faction.OfPlayer` 殖民者生成；
  * **默认自主状态**：英灵默认不属于玩家可直接操纵的殖民者，不开放自由移动、工作分配和征召命令；日常行动由原版 Pawn AI 自主决定；
  * **信赖解锁（后续版本）**：仅在满足后续定义的特殊信赖条件后，才解除自主控制限制并转为可操纵角色；本 MVP 不实现玩家控制权切换；
  * **战备自主迎敌**：战斗期间使用原版 `Duty` / `LordJob` 与 `JobGiver_AIFightEnemies` 驱动自主迎敌。
* **从者战斗与索敌自主性（Servant Autonomy）**：
  * **不受玩家微操直接控制**：实体化状态下的英灵拥有英雄的傲气与战术直觉，不接受玩家框选走位微操；
  * **三阶绝对索敌阶梯（Strict Target Hierarchy）**：
    1. **第一优先级（英灵宿敌）**：战场上存在处于实体化状态的敌对英灵时，**绝对强制优先锁定敌方从者**，无视任何小兵干扰与杂兵阻击；
    2. **第二优先级（敌方御主）**：若敌对从者已灵体化、不可锁定或退场，**立即自动转火直扑敌方御主**（切断契约源头）；
    3. **第三优先级（常规清理）**：若战场已无敌方英灵与御主，回退为原版防卫逻辑，清理其余普通敌对人类、使魔或防御工事；
  * **索敌回退兜底（防 AI 卡死与发呆）**：严格依托上述三阶阶梯执行目标切换，严禁在目标隐形时因空指针陷入原地抽搐与报错死循环；
  * **战备豁免活动区域**：进入战斗状态时，从者自动豁免“限足区（Allowed Area）”限制，防止门禁规则与寻路 AI 发生死锁。
* **战败强制灵体化（原地脱离与倒地解除）**：
  * **统一判定**：原版伤害即将使英灵进入倒地或死亡状态时，统一判定为一次英灵战败；脑、心脏等原版致命部位受损不单独定义为永久死亡；
  * **拦截时机**：仅当普通伤害结算将使原版 `Pawn_HealthTracker` 进入 `MakeDowned` 或死亡流程时，在后续副作用之前由英灵战败处理器统一接管；直接调用 `Pawn.Kill` 不经过该处理；
  * **状态清理**：终止当前 Job、战斗职责、搬运与俘虏相关状态，退出原版倒地/死亡流程；不产生尸体，不掉落装备；
  * **致命损伤最低限度修复**：战败处理器在转换前执行原版生命有效性检查，只修复为避免立即死亡所必需的损坏或缺失部位（例如大脑、心脏）；不修复疼痛、失血、普通伤口或非致命缺失肢体。重新实体化时再次检查，仍会立即倒地或死亡则保持灵体化；
  * **状态转移**：清除英灵的倒地状态并转入【灵体化】，使用统一的半透明表现与原版心理不可见机制实现不可正常索敌的状态；
  * **战败结算代偿**：
    1. 自身当前魔力储备清零；
    2. **强制增加一级永久性的【灵基受损】**（若达第4阶段则真正湮灭消散）；
    3. 挂载**【重新实体化冷却（Re-materialization Cooldown）】**：在冷却倒计时结束前，绝对禁止解除灵体化，处于虚弱凝聚期。
  * **重新实体化前置检查**：冷却结束后，只有当前格满足原版 `Standable`、且保留的伤势不会立即再次触发原版 `MakeDowned` 或 `Kill` 时才允许实体化；处于墙、关闭的门、深水等不可站立格时继续灵体化，不额外清除普通伤势。

### 2. 魔力自愈与绝对流向优先级法则
英灵的肉身由以太魔力编织而成，受创后会自然抽取魔力修补损伤：

* **肉体自愈规则**：
  * 英灵身体存在非缺失性肉体创伤（割伤、烧伤、挫伤等）时，持续自动消耗魔力加速伤口闭合；
  * **缺失类型限制**：断肢、断手断脚等结构性缺失**无法通过魔力自动长出**；
  * **灵体化期的伤势冻结**：灵体化状态下伤口绝不继续流血恶化，是消耗魔力安全疗伤的最佳窗口。
* **绝对魔力流向优先级法则（三级过滤网）**：
  当英灵接收到外来魔力补给时，魔力严格遵循以下顺序依次灌注：

```text
               【外部魔力流入英灵】
                        │
                        ▼
       ┌─────────────────────────────────┐
       │   优先级 1：维持基准线存续      │ ──► 优先填满最低维持线，防止触发断供
       └────────────────┬────────────────┘
                        │ （魔力 > 维持线，盈余部分流向下一级）
                        ▼
       ┌─────────────────────────────────┐
       │   优先级 2：自动治疗肉体创伤    │ ──► 持续消耗魔力加速愈合创伤，直至全身无伤
       └────────────────┬────────────────┘
                        │ （全身创伤彻底痊愈，盈余部分流向下一级）
                        ▼
       ┌─────────────────────────────────┐
       │   优先级 3：蓄积战斗储备池      │ ──► 积攒多余魔力至上限，用于宝具与技能施放
       └─────────────────────────────────┘
```
* **战略拉扯体验**：从者受重伤后，所有供魔会被自愈吃满，根本无法积攒宝具魔力；战后必须留出充分时间让其休养回转。

## 五、 核心机制三：神秘度白名单防御

MVP 神秘度只作为“英灵施放的攻击能否伤及实体化英灵”的白名单门，不建立等级比较、独立伤害公式或第二套护甲系统。

* **判定规则**：
  * 伤害施放者为实体化英灵时，伤害完整进入原版伤害、护甲、部位、流血、倒地与战败判定流程；
  * 其他来源对实体化英灵的伤害在原版伤害应用前被拦截，不造成生命值、出血、部位损伤或灵基受损；
  * 普通原版武器和高科技物理武器均不因科技等级自动获得穿透资格。魔术、特殊武器及其他体系的白名单扩展留待后续阶段。
* **原版复用边界**：
  * 拦截仅作为原版伤害入口的前置守门，不重写伤害结算；被拦截的攻击使用跳弹/火花与音效作为反馈。
  * 灵体化的不可攻击性仍由灵体状态系统负责，不依赖神秘度规则重复判定。
  * 直接 `Kill` 不拦截；普通伤害即将使从者倒地或死亡时才进入战败灵体化处理。

## 六、 核心机制四：御主资格、令咒与战争开启（Trigger & Progression）

### 1. 御主资质与令咒（Master Traits）
* **【魔术师位阶特质】（七阶分级，源自时钟塔）**：
  * 等级由高至低：**冠位（Grand）、色位（Brand）、典位（Pride）、祭位（Fes）、开位（Cause）、长子（Count）、末子（Frame）**；
  * **初期实现原则**：纯身份标签特质，**先不附加复杂的原版属性加成**，仅作为拥有魔术回路的身份判定与未来魔术师体系的地基。
* **【魔术回路特质】（独立天赋）**：
  * 回路数量、质量与供魔安全线由独立的“魔术回路” Trait 决定；该 Trait 的 `DefModExtension` 引用 `MasterCircuitDef`，从而派生御主魔力上限、自然回复和安全线；
  * MVP 中安全线以 `supplyThresholdFraction` 表示为最大御主魔力的比例，由独立阈值策略计算；后续可由策略扩展普通/战斗两档或其他模式，不改变供魔结算流程；
  * 选中玩家御主时显示独立的御主魔力槽及安全线指针。玩家可按 5% 步进调整个人安全线或恢复回路默认值；显示与设置组件不保存魔力，也不依赖原版灵能、冥想或灵能热系统；
  * 每名御主在 MVP 中只拥有一个有效回路 Trait。它与魔术师位阶 Trait 不互相替代，也不在 Pawn 组件中重复保存回路数值。
* **【令咒特质】（Command Spells）**：
  * 单独特质，仅作为御主拥有令咒资格的身份标识；当前剩余计数由御主状态组件维护，初始为 3 划；
  * **注销逻辑**：仅当组件中的令咒计数消耗至 $\le 0$ 时才移除该特质，为未来的令咒抢夺与补充预留空间；
  * **当前阶段唯二战略效果**：
    1. **奇迹重铸**：瞬间清除目标英灵身上的所有【灵基受损】创伤（当前阶段唯一修复途径）；
    2. **宝具过载**：使英灵下一次宝具解放**无需消耗自身魔力，且威力大幅增强**。

### 2. 召唤与触发双轨制（兼容剧本与现有存档）
* **双轨接入**：
  * **专属剧本开局**：初始小人自带【魔术师】与【令咒】特质；
  * **常规存档触发**：只要殖民地存在拥有任一等级【魔术师】特质的小人，后台将小概率刷出稀有任务【降灵之兆：英灵召唤】。
* **绝对自主可控**：玩家不主动派遣魔术师接取并完成召唤任务，**圣杯战争绝对不会强制开启**，绝不打扰普通种田玩家。
* **早期召唤仪式（极简特殊行动）**：
  * **前期敏捷开发**：不做复杂的祭坛建筑或圣遗物收集，直接做成一项由魔术师释放的**专属特殊行动（Gizmo / Ability）**；
  * **单从者绝对锁定**：谁释放该行动，召出的英灵就与谁契约绑定；**前期锁定玩家基地同时只能存在一骑己方英灵**，当已有英灵存活现世时，其他魔术师的召唤行动直接置灰失效；
  * **相性随机出货**：从当前已完成的可用英灵库（如阿尔托莉雅、红A等）中随机响应显现。
* **战争发令枪**：玩家成功召唤第一骑英灵的刹那，全图通告开幕，敌对阵营后台生成完毕，突袭机制正式运转。

## 七、 阶段二以后：战争主线循环、博弈与突袭节奏

圣杯战争不是一次性的通关事件，而是一场**具有紧迫军备竞赛感的动态生存拉锯**。

### 0. 战争时间状态
* **唯一全局状态参数**：记录圣杯战争开始时刻，并由当前游戏时间计算【圣杯战争天数】；
* 所有随战争时间变化的规则均从【圣杯战争天数】派生，不额外保存战争阶段、成长计数或重复的全局进度字段；
* 第一版唯一的自定义全局存档值为 `warStartTick`：战争未开始时为 `-1`，战争开始后记录 `Find.TickManager.TicksGame`；战争天数按 `(TicksGame - warStartTick) / 60000f` 实时派生；
* 己方从者、御主、令咒和敌对参与者的局部状态不属于战争全局进度，不违反单一战争时间状态约束；
* 敌方成长、事件频率和其他时间相关规则另行定义。

```text
               ┌─────────────────────────────────────┐
               │    开启圣杯战争（召唤第一骑英灵）    │
               └──────────────────┬──────────────────┘
                                  ▼
      ┌─────────────────────────────────────────────────┐
      │            和平发展期：魔力收集与军备竞赛         │
      │  • 精炼魔力、物理进食转魔、维持英灵灵基稳固     │
      │  • 准备战斗武装、防范突袭                       │
      └───────────────────────┬─────────────────────────┘
                              │
               【突发事件：敌对从者潜入突袭】（仅御主在基地时触发）
                              │
                              ▼
      ┌─────────────────────────────────────────────────┐
      │                  遭遇战胜负分支                  │
      ├────────────────────────┬────────────────────────┤
      │ [玩家防守失败/英灵败退] │ [成功击退敌方英灵]      │
      ├────────────────────────┼────────────────────────┤
      │ • 己方原地强制灵体化   │ • 敌方原地灵体化败退   │
      │ • 己方灵基加重一级受损 │ • 敌方灵基加重一级受损 │

               ┌────────────────────────────────────────┐
               │          趁虚而入：最佳反击窗口         │
               │  • 侦察敌方大地图据点坐标             │
               │  • 奔袭敌方据点，执行御主斩首/补刀从者 │
               └───────────────────┬────────────────────┘
                                   ▼
               ┌────────────────────────────────────────┐
               │       彻底灭灯：彻底淘汰一组竞争对手   │
               │  • 斩首敌方御主 或 让敌方英灵灵基崩溃消散│
               │  • 夺取战利品，距离大圣杯更进一步       │
               └────────────────────────────────────────┘
```

### 1. 触发规则与环境限定
* **触发前提**：仅当玩家阵营拥有**【激活的御主小人处于当前大本营】**时，才会触发敌方从者的针对性突袭（暗杀/正面攻坚）。
* 避免了御主不在家时老巢被单方面拆家或机制错乱的尴尬。

### 2. 敌对大地图据点生成（极简构架）
* **前期极简原则**：不引入复杂的使魔大军与迷宫结构，每个据点仅由**【1 名敌方御主 + 1 骑敌方从者】**构成。
* **淘汰判准**：玩家带队进攻敌方据点，只要**击杀敌方御主**或**将敌方从者打至【灵基受损阶段 4（湮灭）】**，该据点直接判定拔除。

### 3. 动态压力与军备竞赛（Arms Race）
* **时间压力机制**：圣杯战争随着时间推进，外界残留的敌对从者也会在暗中汲取魔力、不断变强。
* **逼迫主动破局**：如果玩家一味筑墙死守，后续来袭的从者将携带更充沛的魔力量，造成极大防守压力。玩家必须主动在防守反击中寻找战机。

### 4. 彻底淘汰敌对阵营的判准
* **胜利条件（二选一）**：
  1. **斩首敌方御主**：断绝其魔力源头与契约，使敌方从者失去后方支持。
  2. **持续重创敌方从者**：通过多次防守反击或强攻其据点，使其**【灵基受损达到第4阶段】**，因伤重无法维持而彻底消散。

## 八、 引擎底层健壮性与避坑准则（面向代码实现的硬约束）

为了确保后续交给代码生成模型时零逻辑死锁与零性能隐患，确立以下 4 条底层硬规范：

1. **零性能开销保障**：
   * 御主与从者的供魔计算只涉及相关 Pawn 的简单数值换算，严禁使用全图 Tick 级无脑遍历，统一采用 60 ~ 250 ticks 的低频轮询；
   * 各组件只维护自身相关对象，避免重复扫描和重复保存状态。
2. **防 AI 目标丢失死锁（严格三阶索敌兜底）**：
   * 敌方从者严格遵循【英灵 > 御主 > 其他人/建筑】的索敌三阶法则：若上级目标不可索敌或已退场，立即回退到下一级目标，严禁因目标失效产生原地发呆、空引用或重复报错。
3. **活动区域限制（Allowed Area）豁免**：
   * 从者进入战备状态自主寻路出击时，强制忽略玩家的“安全区/门禁区”限制，防止门禁碰撞与寻路打架。
4. **战败拦截时序（Death / Downed Boundary）**：
   * 对将造成倒地或死亡的普通伤害，战败处理必须位于原版 `MakeDowned` / 死亡副作用之前，先终止相关 Job、Lord 和搬运/俘虏状态，再进入灵体化；直接 `Pawn.Kill` 保持原版直死，不得依赖死亡后的尸体复活或事后清理。

## 九、 第一版状态与变量归属

为避免多个模块各自保存同一状态，所有变量必须先确定唯一归属。能够由原版对象或当前状态推导的内容不重复存档。

### 1. 全局战争组件

* `warStartTick`（`int`，存档）：唯一的自定义全局战争时间状态；未开始为 `-1`。
* `warDays`（`float`，不存档）：由当前 Tick 和 `warStartTick` 派生。
* `warIsActive`（`bool`，不存档）：由战争时间和原版任务生命周期派生。

### 2. 从者状态组件

* `master`（`Pawn`，存档）：契约御主，使用原版 Pawn 引用存储。
* `presenceState`（枚举，存档）：实体化、主动灵体化、战败灵体化、湮灭；“重新实体化中”只是冷却结束后的短暂状态转换，不作为长期存档状态。
* `rematerializationReadyTick`（`int`，存档）：重新实体化的绝对 Tick；不保存剩余天数。
* `defeatResolutionInProgress`（`bool`，运行时）：战败拦截的递归保护，不存档。
* 魔力、维持、断供与自愈均由单一低频结算服务按共享周期调度，不在单个从者组件保存下次结算 Tick。

从者当前地图、位置、Job、Lord、当前目标和活动特效均由原版运行时对象提供，不作为从者存档字段。

### 3. 御主魔力与供魔

* `Need_MasterPrana.CurLevel`（`float`，由 Need 系统存档）：御主当前魔力，唯一数值来源。
* `Need_MasterPrana.MaxLevel`、自然回复速率和供魔安全线（静态配置）：由御主的魔术回路数量与质量天赋派生；魔术师位阶 Trait 只承担身份标识，不参与该数值计算。
* 御主与从者共用一次统一的低频魔力结算服务；结算周期由共享静态配置决定，不单独保存御主供魔调度字段。
* 供魔对象由从者 `master` 引用在运行时建立索引，不在御主侧重复保存契约从者列表。
* 每次供魔只纳入未满魔、实体化的契约从者；满魔者立即退出均分池。御主死亡时，其所有未湮灭的契约从者立即转为湮灭。

### 4. 从者魔力、断供和灵基状态

* `Need_Prana.CurLevel`（`float`，由 Need 系统存档）：当前魔力；不得再由其他组件保存一份 `currentPrana`。
* `Need_Prana.MaxLevel`（`float`，由身份配置派生）：最大魔力上限。
* `materializedSustainThreshold`、`spiritSustainThreshold`、`upkeepPerDay`、`spiritUpkeepMultiplier`、`shortageDurationTicks`（静态配置）：实体化/灵体化的维持规则和断供恶化时长。
* `Hediff_ServantPranaShortage`：存在即表示当前断供，其原版 `ageTicks` 记录连续断供时间；不在从者组件中另存开始 Tick、经过 Tick 或活动标记。
* `Hediff_ServantSpiritDamage.Severity`（`float`，存档）：灵基受损阶段 0 到 4；不另存一份 `spiritDamageStage`。

### 5. 进食转魔

* `Need_Food.CurLevel`（`float`，由原版 Need 系统存档）：食物营养储备。
* `foodConversionThreshold`（静态配置）：与原版进食 Job 启动边界一致的转化阈值。
* `foodToPranaRate`（静态配置）：饥饿值转化为魔力的速率。
* 原版自然饥饿下降必须关闭；自定义转魔模块是唯一的自然下降来源。
* 仅实体化从者可以进食和转魔；灵体化期间 `Need_Food` 保持不变。
* 转魔模块不得自行创建第二套寻食 Job，必须复用原版食物选择、进食和食物限制逻辑。

### 6. 神秘度白名单

* MVP 不保存 `hasMystery` 或神秘度等级字段；伤害施放者是否为实体化英灵由 `DamageInfo` 的原版运行时施放者引用与从者状态实时判定。
* 攻击源当前的 `DamageInfo`、投射物、施放者与命中上下文均为原版运行时数据，不另行存档。
* 后续特殊攻击来源采用独立的静态白名单 Def 扩展；该扩展不属于当前 MVP 数据模型。

### 7. 御主和令咒

* `commandSpellCharges`（`int`，御主组件存档）：当前剩余令咒，初始为 3。
* 令咒特质只承担身份标识；动态计数不放入 Trait 对象。
* “宝具过载”使用后保存 `noblePhantasmOverchargePending`（`bool`，御主组件存档）；它只作用于目标从者下一次成功释放的宝具，MVP 不设置超时字段。

### 8. 身份 Def 中的静态配置

身份模板只保存不会随游戏过程变化的配置，例如：

* `servantKind`、固定姓名、性别、外观、初始装备和身份特征；
* `maxPrana`、实体化维持消耗、灵体化维持倍率、两种维持阈值；
* 灵体正常跟随距离、闪现触发距离和闪现落点半径；灵体共通移速倍率直接配置在灵体 Hediff 中；
* 进食转魔速率、自愈间隔、自愈魔力消耗和非致命缺失部位规则；
